# Savegame Renamer — звуки интерфейса

Дизайн, 19.08.2026. Спецификация мода:
[2026-08-17-savegame-renamer-design.md](2026-08-17-savegame-renamer-design.md).

## Задача

Диалог переименования молчит: наведение на подсказку, подтверждение, отмена и
отказ не звучат никак, тогда как всё остальное меню вокруг него озвучено. Мод
собран из штатной графики игры и должен звучать так же штатно.

Берутся звуки самой игры по имени триггера. Ни одного своего звукового файла мод
не несёт и ни одного не подменяет.

## Проверенные факты

Установлено на версии игры `1.5.6-15693-release_1_5` разбором `Data/IPL_GameData.pak`,
`Bin/Win64MasterMasterSteamPGO/WHGame.dll` и заголовков libKCD2.

### Как звук доходит из flash до игры

`wh::guimodule::C_UICommonEventHandler` — сквозной приёмник fscommand, который
регистрируется на **каждом** flash-элементе под отладочным именем
`CommonEventHandler`: его `Init` обходит список элементов `g_pFlashUI`, а путь
перепривязки `C_UIFlashBase` цепляет его заново поэлементно. Приёмник разбирает
имя события строкой и на `OnPlayAudio`, `OnStopAudio`, `OnSetVolumeAudio`
вызывает аудиосистему. Разбор в
`include/guimodule/C_UICommonEventHandler.h` библиотеки
[libKCD2](https://github.com/JerryYOJ/libKCD2).

Элемент мода под это правило подпадает наравне с ванильными, отдельной регистрации
не требуется. Требуется объявить событие: ванильные `UIElements/*.xml` объявляют
все три, а `SavegameRenamer.xml` не объявляет ни одного, поэтому звука сейчас и
нет.

### Имена триггеров

Каждая ванильная `.gfx` несёт AS2-класс `Audio` (пакет `__Packages.Audio`). Он
оказался тонкой обёрткой: `Audio.Play(triggerName)` сводится к
`ExternalInterface.call("onPlayAudio", triggerName)`, а всё остальное в классе —
таблица констант с именами триггеров. Семейство меню из этой таблицы:

| Константа | Триггер |
|---|---|
| `MENU_OPEN` | `ui_menu_open` |
| `MENU_CLOSE` | `ui_menu_close` |
| `MENU_CHANGE_FOCUS` | `ui_menu_change_focus` |
| `MENU_CHANGE_CHOICE` | `ui_menu_change_choice` |
| `MENU_CHANGE_VALUE` | `ui_menu_change_value` |
| `MENU_ENABLE` | `ui_menu_enable` |
| `MENU_DISABLE` | `ui_menu_disable` |

Класс несёт ещё три семейства: `APSE_*` для кодекса, инвентаря, карты, `QAM_*`
для колеса быстрого доступа и `PICKPOCKET_*`. Они не берутся: диалог стоит
поверх списка сохранений, то есть внутри `Menu.gfx`, и звук из другого экрана
там прочитается как чужой. Семейство меню закрывает все нужные случаи целиком,
смешивать нечего.

### Что играет ванильное меню

`Menu.gfx` вызывает `Audio.Play` ровно один раз, и то на закрытие экрана справки:
собственные звуки клика и наведения главное меню играет из нативного кода, минуя
flash. Отсюда следствие для проверки: имена `ui_menu_*` в шапке `WHGame.dll`
присутствуют, но вызова из flash за ними в игре не стоит ни одного. Вызовы из
flash доказанно работают у семейства `APSE_*` — например `ApseInventoryList.gfx`
играет `ui_apse_select` при выборе предмета.

## Раскладка

| Момент | Триггер |
|---|---|
| F2 открывает окно | `ui_menu_open` |
| наведение на строку подсказки | `ui_menu_change_focus` |
| Enter, подтверждение | `ui_menu_change_choice` |
| Esc, отмена | `ui_menu_close` |
| Del, сброс доступен | `ui_menu_change_choice` |
| Del, сброс недоступен | `ui_menu_disable` |

Подтверждение и отмена различимы на слух, как это устроено в самом меню. Клик
мышью по строке подсказки идёт через тот же `fc_setInput`, что и клавиша, поэтому
одна точка вызова покрывает оба способа ввода и они не могут разойтись.

## Изменения

### `src/Data/Libs/UI/UIElements/SavegameRenamer.xml`

В блок `<events>` элемента `SavegameRenamer` добавляется одно объявление,
дословно как в ванильном `Menu.xml`:

```xml
<event name="OnPlayAudio" fscommand="onPlayAudio" desc="execute global audio trigger">
  <param name="TriggerName" desc="" type="string" />
</event>
```

`OnStopAudio` и `OnSetVolumeAudio` не объявляются: играются только короткие
однократные триггеры, останавливать и приглушать нечего.

Элемент `SavegameRenamerHint` не трогается. Он не берёт ни мышь, ни клавиатуру и
объявляет только `SetLabels` и `ShowHint`, ни одна из которых не звучит.

### `flash/renamer.as`

Константы имён, обёртка и шесть точек вызова.

```as
function playAudio(trigger) {
    fscommand("onPlayAudio", trigger);
}
```

Обёртка идёт через `fscommand`, а не через `flash.external.ExternalInterface.call`,
как ванильный класс `Audio`: собственные события мода уже ходят через `fscommand`
с этого же элемента и доходят, так что этот путь и проверен на самом элементе, и
привычен файлу.

Точки вызова:

- `fc_open`, последней строкой, когда окно уже поднято и фокус выставлен;
- `onRollOver` внутри `mkKeyHint`, рядом с подсветкой подписи;
- три ветки `fc_setInput` плюс ветка отказа, которой сейчас нет: `reset` при
  скрытой строке сброса не делает ничего и получает `else`.

Константы и обёртка объявляются по правилам файла: одно объявление на `var`,
без объектных литералов и тернарных операторов, чтобы парсер FFDec принял.

### Чего не меняется

- C++ не трогается. Слушатель в `RenameDialog.cpp` сравнивает имя события со
  своими тремя и незнакомые молча пропускает, так что объявленное сверх них ему
  ничего не стоит.
- Локализация не трогается: новых строк мод не заводит.
- `src/Data/Libs/UI/renamer.gfx` и `src/Data/savegame_renamer.pak`
  пересобираются как обычно, оставаясь воспроизводимыми.

Ловушка на будущее: `renamer.gfx` заряжен в два элемента сразу, и звук,
поставленный в функцию, которую плагин зовёт на обоих, прозвучит дважды. Ни одна
из шести точек вызова на элементе подсказки не достижима, но новую точку следует
сверять с этим списком.

## Проверка

Файлами не проверяется, только на слух в игре.

```sh
python tools\build.py --deploy
```

1. Открыть список сохранений: подсказка F2 молчит, как и раньше.
2. Нажать F2: окно поднимается со звуком открытия меню.
3. Поводить мышью по строкам Enter, Esc, Del: каждый вход в строку щёлкает.
4. Enter и Esc: звуки различаются между собой.
5. Del на сохранении с припрятанным оригинальным именем: звук подтверждения.
6. Del на сохранении без него: отказной звук, окно остаётся открытым.

## Запасные пути

Если тишина сохранится, отказывать могут две разные вещи, и они разделяются:

- **Имя.** Подставить `ui_apse_select` вместо `ui_menu_change_choice`. Зазвучало —
  механизм рабочий, а `ui_menu_*` из flash не резолвится, и раскладка целиком
  переезжает на `APSE_*`.
- **Канал.** Заменить `fscommand` на `flash.external.ExternalInterface.call`, как
  в ванильном классе `Audio`. Зазвучало — дело в канале, а не в имени.
