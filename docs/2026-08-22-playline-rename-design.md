# Savegame Renamer — имена игровых линий

Дизайн, 22.08.2026. Спецификация мода:
[2026-08-17-savegame-renamer-design.md](2026-08-17-savegame-renamer-design.md).

## Задача

С экрана «Выбор игровой линии» игрок видит пять строк вида «Линия игры N».
Номер слота не говорит ничего о прохождении, а второй строкой игра показывает
квест, часы и дату последнего сохранения — сведения, которые меняются с каждым
автосейвом. Прохождения различают по этой второй строке, и она уплывает.

Мод даёт линии собственное имя: заголовок строки, который игрок задаёт сам и
который не меняется, пока он его не сменит. Задаётся тем же F2 и тем же
диалогом, что и имя сохранения.

## Проверенные факты

### Что игра рисует

Строки экрана строит `C_UISaveLoad::AddPlaylineButtons` (`REL::ID(95)`,
`0x182BAA55C`): пять вызовов flash-функции `AddPlaylineButton`. Объявление в
`Libs/UI/UIElements/Menu.xml` игры даёт ей пять параметров: `playlineIdx`,
`uiText`, `data`, `tooltip`, `disable`.

`uiText` — это заголовок, и собирает его сторона C++ из `ui_Playline %d` плюс
`ui_PlaylineEmpty` либо `ui_PlaylineHardcore`. Все четыре ключа лежат в
`text_ui_menus.xml`.

`fc_addPlaylineButton` в `Menu.gfx` кладёт строку под тип `PlaylineButton`,
запоминает в ней `playlineIdx` и раскладывает текст по `tfHead` и `tfSub`; копия
заголовка остаётся в `uiHead`, откуда движок берёт его при выделении.

### Откуда берётся подзаголовок

`tfSub` собирается из `data`, разрезанного по вертикальной черте, по полям 2, 6
и 7. Поле 2 — `whs::UiField::Quest`, то самое, куда мод пишет пользовательское
имя сохранения. Проверено в игре: переименованный последний сейв линии виден в
её подзаголовке. Значит грубая метка у игрока есть уже сегодня, но живёт она в
чужом поле и слетает со следующим сохранением.

### Чего у линии нет

Линия существует только как каталог `saves/playlineN/` с файлами `*.whs` внутри.
Ни файла свойств, ни имени, ни идентификатора. Хранилище заводит мод — впервые
за свою историю.

Игра терпима к написанию каталога: вручную созданный `playline01` она показала
как «Линия игры 2». Сама она пишет `playline` и число без ведущих нулей.

### Что можно писать во flash

`IFlashVariableObject::SetMember` в libKCD2 есть (слоты 7 и 8). Обход
`_root.MenuManagerArray`, которым `MenuSelection` уже читает выделение, годится и
для записи.

## Решения

| Вопрос | Решение |
|---|---|
| Что показывает имя | заголовок вместо «Линия игры N»; подзаголовок игры не трогается |
| Где хранится | файл в каталоге линии |
| Где работает | показ на обеих страницах линий, правка только на странице загрузки |
| Пометка о хардкоре | остаётся после имени |

## Раскладка

### `whs/Playline` — переименованный `whs/Saves`

`whs/Saves` нёс одну функцию и назывался по месту, а не по предмету. Все функции
модуля принимают корень сохранений и индекс линии, то есть модуль про линию.

```cpp
struct PlaylineLocation {
    std::filesystem::path dir;
    int matches = 0;      // 0 нет, 1 нашли, >1 отказ по неоднозначности
};

PlaylineLocation           FindPlaylineDir(root, index);
bool                       PlaylineHasSaves(root, index);
std::string                PlaylineName(root, index);
bool                       SetPlaylineName(root, index, name);
std::optional<Description> FindPlaylineSave(root, index, fileName, saveId);
```

Перечисление каталогов, заявляющих индекс, приватно в `.cpp`: имя каталога
сопоставляется по числу, которым оно кончается, а не по тексту, чтобы читать то
же, что читает игра. `FindPlaylineDir` сводит перечисление к одному ответу со
счётчиком; `FindPlaylineSave` идёт по всем кандидатам сам.

`PlaylineHasSaves`, `PlaylineName` и `SetPlaylineName` работают с одним
каталогом и потому идут через `FindPlaylineDir`, отказывая при любом числе
совпадений, кроме единицы. `SetPlaylineName` пропускает ввод через
`SanitiseName`, как это делает `Description::SetDisplayName`.

Модуль от игры не зависит и собирается в тестовый исполняемый файл, как
`Description` и `Sanitise`.

### `game/MenuSelection`

Добавляется `int PlaylineIndex()`: `playlineIdx` выделенной строки, когда её тип
`PlaylineButton`, иначе -1. Тот же обход, что у `SaveId()`.

### `game/SaveLoadHook`

`PreparePage` уже получает номер страницы. Обработчик вместо булева признака
принимает страницу перечислением, которым владеет сам модуль:

```cpp
enum class Page { SaveList, PlaylineLoad, PlaylineNew, Other };
Page CurrentPage();
```

Номера 8, 7 и 4 остаются внутри хука. `RenameFlow` по-прежнему решает, где
показывать подсказку; F2 по строке линии отпирается только на `PlaylineLoad`.

### `game/PlaylineLabels` — новый

Хук на `AddPlaylineButtons`. После оригинала обходит `_root.MenuManagerArray`,
берёт строки типа `PlaylineButton`, читает `playlineIdx` и, когда у линии есть
имя, переписывает `tfHead.text` и `uiHead`. Заголовок собирается как имя плюс
хвост игры, если он был: ключ хардкора резолвится через тот же
`Strings::Localize`, что и всё остальное.

Здесь же исполняется правило переиспользования слота: строка линии без
сохранений стирает её имя и остаётся ванильной. Это единственное место, которое
удаляет имя само по себе, без участия игрока.

Наружу отдаёт `Repaint()`, чтобы переименование обновило экран, не пересобирая
страницу. Строители страниц 7 и 4 при этом не нужны, и их адреса не берутся.

### `game/RenameFlow`

Диалог один на весь мод, его обработчики глобальны, поэтому владелец знает обоих
подопечных. `Pending` получает признак предмета:

```cpp
enum class Subject { Save, Playline };
```

`OpenFor` становится `OpenForSave`, рядом встаёт `OpenForPlayline`; `ApplyRename`
расходится на две ветки в одном месте. Появится третий предмет — это станет швом
с двумя реализациями; на двух он лишний.

Диалог открывается на текущем имени линии, а на безымянной — пустым: заголовок
там принадлежит игре, и подставлять «Линия игры 2» в поле ввода значило бы
предлагать игроку записать шаблон как своё имя. Кнопка сброса доступна, когда имя
есть, и стирает его, возвращая ванильный заголовок.

### `plugin.cpp`

Слушатель F2 спрашивает `MenuSelection::SaveId()`, а если страница
`PlaylineLoad` — `MenuSelection::PlaylineIndex()`. Само-запирание сохраняется:
обе функции отдают -1 везде, кроме своих строк.

### Локализация

`src/Localization/strings.xml` получает заголовок диалога и текст подсказки для
линии. Остальное берётся из таблиц игры и перевода не требует.

## Хранилище

`saves/playlineN/savegame_renamer.name`, одна строка UTF-8 без завершающего
перевода. Разбора нет: содержимое файла и есть имя.

Файл лежит рядом с тем, что именует. Он уезжает с резервной копией каталога,
имеет шанс попасть в Steam Cloud и правится блокнотом. Игра перебирает только
`*.whs`, так что для неё его нет.

Пустое имя удаляет файл, как пустой ввод сбрасывает имя сохранения.

## Правило переиспользования слота

Индекс линии переживает её удаление, имя — не должно: игрок удаляет линию 2,
начинает новую игру в том же слоте и не должен унаследовать чужую метку.

Правило: **имя, лежащее в линии без единого `.whs`, считается чужим и удаляется
при первом же взгляде на страницу.** Проверяется с диска через
`PlaylineHasSaves`, не требует ни хука на удаление, ни события, и срабатывает
раньше, чем игрок успеет увидеть метку: строку пустого слота игра рисует в любом
случае.

## Неоднозначность каталога

Два каталога могут заявить один индекс: `playline1` рядом с `playline01`. Игра
такого не создаёт — нужна рука человека, — но случай разбирается отдельно,
потому что близкая по форме защита в переименовании сохранений уже приводила к
тихому отказу на штатной конфигурации.

Разница в частоте. Совпадение `SaveId` встроено в модель данных: нумерация
попланлайновая, поэтому две линии обязаны иметь `save001.whs` с `SaveId 1`, и
отказ срабатывал у каждого, кто вёл два прохождения. Совпадение имён каталогов
игра создать не может.

Общий дефект не в отказе, а в молчании, и лечится он здесь:

- `FindPlaylineDir` отдаёт число совпадений, поэтому игровой слой различает «нет
  такого каталога» и «их два» и пишет в лог разное. Логирования в `whs` при этом
  не появляется.
- `FindPlaylineSave` **не разрешает каталог заранее**: он идёт по всем
  кандидатам и отказывает, только если нужный файл с нужным `SaveId` нашёлся в
  двух. При штатной раскладке кандидат один и поведение то же, что сейчас, а при
  рукотворном дубликате переименование сохранений продолжает работать всюду,
  кроме точной копии каталога. Иначе отказ по каталогу убивал бы и переименование
  сохранений, а не только имена линий.
- Имя линии так разрешить нельзя: записать его можно лишь в один каталог, а
  показать имя из каталога, который игра не читает, значит соврать. Там отказ
  остаётся, но он изолирован от сохранений.

Строгое сравнение имени каталога, которое убрало бы неоднозначность совсем, не
берётся: игра сама терпима к написанию, мод должен читать то же, что читает она,
а угадывание «какой из двух каталогов её» — единственный вариант, способный
записать имя в чужое прохождение.

## Отказы

| Что случилось | Что видно |
|---|---|
| Имени нет | ванильный заголовок, мод не вмешивался |
| Файл имени нечитаем или пуст | как будто имени нет |
| Линия без сохранений | имя удаляется, заголовок ванильный |
| Индекс заявлен двумя каталогами | имя не показывается, F2 по строке молчит, причина в лог |
| Нужный файл нашёлся в двух каталогах | переименование сохранения отказывает, причина в лог |
| Запись имени не удалась | строка остаётся прежней, причина в лог |

## Проверка

Синтетика на временном дереве каталогов, рядом с тестами `whs/Playline`:

- круг «записать имя, прочитать, стереть»;
- имя в линии без сохранений сбрасывается;
- битый и пустой файл имени читаются как отсутствие имени;
- юникод и обрезка краёв проходят через `SanitiseName`;
- индекс, заявленный двумя каталогами: `FindPlaylineDir` даёт два совпадения;
- тот же случай для `FindPlaylineSave`: файл лежит в одном каталоге — находится,
  в обоих — отказ.

В игре: стенд с двумя линиями. Имя видно на обеих страницах линий, переживает
выход в игру и возврат, не появляется у пустого слота после удаления линии.

## Запасные пути

Дорисовка строк пишет в ролик после раскладки. Если выделение или обрезка будут
спорить с записью, следующий шаг — подменять `uiText` на входе во flash, до того
как ActionScript его разложит: игра тогда сама делает и `tfHead`, и `uiHead`, и
цвет. Цена — отдельная работа по реверсу того, откуда игра зовёт
`AddPlaylineButton`; в libKCD2 этого сейчас нет. Меняется при этом один модуль,
`PlaylineLabels`.

Подмена локализации `ui_Playline` не годится: строка одна на все пять кнопок, и
в момент её разрешения индекса ещё нет.

## Чего не делается

Правки с экрана новой игры, значков и цветов у линий, переноса имён между
слотами, сортировки линий. Ничего из этого не просили.
